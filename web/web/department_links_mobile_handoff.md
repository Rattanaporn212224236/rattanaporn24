# สรุปสำหรับผู้ดูแลเซิร์ฟเวอร์แอปมือถือ: ตาราง `department_links`

## ปัญหาที่แก้
บางภาควิชาและบางหลักสูตรในฐานข้อมูล `kuse_event` เป็นหน่วยงานเดียวกันจริง ๆ แค่ถูกเก็บเป็นคนละแถวในตาราง
`departments` (คนละ `cat_id`) เช่น "ภาควิชาวิศวกรรมไฟฟ้าและคอมพิวเตอร์" กับ "หลักสูตรวิศวกรรมไฟฟ้า" +
"หลักสูตรวิศวกรรมคอมพิวเตอร์" เดิมไม่มีความเชื่อมโยงกันในฐานข้อมูลเลย ทำให้กิจกรรมที่แอดมินโพสต์ผ่านภาควิชา
ไม่ถูกนับรวมเวลานิสิตเปิดดูย้อนหลังผ่านหน้าหลักสูตรที่เชื่อมกัน

เว็บแอดมิน (โปรเจกต์นี้) ได้สร้างตาราง `department_links` ไว้ในฐานข้อมูลที่ใช้ร่วมกันแล้ว และปรับ query
ฝั่งเว็บแอดมินให้ใช้ตารางนี้แล้ว **แต่แอปมือถือรันคนละเซิร์ฟเวอร์ ไม่ได้ใช้โค้ดร่วมกัน** จึงต้องเพิ่ม logic
ฝั่งแอปมือถือเองด้วย ถึงจะเห็นผลจริงตอนนิสิตเปิดแอป

## โครงสร้างตาราง `department_links`
```sql
CREATE TABLE department_links (
  id INT AUTO_INCREMENT PRIMARY KEY,
  dept_id INT NOT NULL,          -- อ้างอิง departments.dept_id (ฝั่งภาควิชา)
  related_dept_id INT NOT NULL,  -- อ้างอิง departments.dept_id (ฝั่งหลักสูตรที่เชื่อมกัน)
  UNIQUE KEY uniq_department_link (dept_id, related_dept_id),
  FOREIGN KEY (dept_id) REFERENCES departments(dept_id) ON DELETE CASCADE,
  FOREIGN KEY (related_dept_id) REFERENCES departments(dept_id) ON DELETE CASCADE
);
```
ความสัมพันธ์เก็บทิศทางเดียว (ภาควิชา → หลักสูตร) แต่ต้องอ่านแบบสองทิศทางเสมอ จึงสร้างวิวช่วยไว้ให้อีกชั้น:

```sql
CREATE OR REPLACE VIEW department_link_closure AS
SELECT dept_id, dept_id AS linked_dept_id FROM departments
UNION
SELECT dept_id, related_dept_id AS linked_dept_id FROM department_links
UNION
SELECT related_dept_id AS dept_id, dept_id AS linked_dept_id FROM department_links;
```
วิวนี้อ่านง่ายกว่า: query แค่ `WHERE dept_id = X` ก็ได้ครบทั้ง X เอง + หน่วยงานที่เชื่อมกันทุกทิศทางในคำตอบเดียว

## คู่ที่เชื่อมไว้แล้วตอนนี้ (ยืนยันรายชื่อจริงกับอาจารย์/ผู้ดูแลระบบแล้ว)
| ภาควิชา | หลักสูตรที่เชื่อมด้วย |
|---|---|
| ภาควิชาวิศวกรรมเครื่องกลและการผลิต | วิศวกรรมเครื่องกลและการผลิต, วิศวกรรมอุตสาหการ |
| ภาควิชาวิศวกรรมไฟฟ้าและคอมพิวเตอร์ | วิศวกรรมไฟฟ้า, วิศวกรรมคอมพิวเตอร์ |
| ภาควิชาวิศวกรรมโยธาและสิ่งแวดล้อม | วิศวกรรมโยธา, วิศวกรรมสิ่งแวดล้อมเพื่อการพัฒนาอย่างยั่งยืน |
| ภาควิชาวิทยาการคอมพิวเตอร์และสารสนเทศ | วิทยาการคอมพิวเตอร์ |
| ภาควิชาวิทยาศาสตร์ทั่วไป | เคมีประยุกต์ |

## สิ่งที่ต้องเพิ่มในเซิร์ฟเวอร์แอปมือถือ (ยังจำเป็นอยู่ — ดูหัวข้อ "ทำไมมีข้อมูลในฐานข้อมูลแล้วแต่แอปยังไม่เห็นผล" ด้านล่าง)

เพื่อให้ง่ายที่สุด เราสร้างวิว (VIEW) ชื่อ `department_link_closure` ไว้ในฐานข้อมูลให้แล้ว
วิวนี้คำนวณ UNION ให้เสร็จเรียบร้อย ไม่ต้องเขียน query ซับซ้อนเองอีก แค่ query วิวนี้ตัวเดียวก็พอ:

```sql
-- ได้ dept_id ทั้งหมดที่ "เกี่ยวข้อง" กับ dept_id ที่กำลังดู (รวมตัวเองอยู่แล้วเสมอ ไม่ต้องเติมเอง)
SELECT linked_dept_id FROM department_link_closure WHERE dept_id = :target_dept_id;

-- แล้วเอา id ทั้งหมดที่ได้ไปกรองกิจกรรมโดยตรง
SELECT e.* FROM events e
WHERE e.dept_id IN (
  SELECT linked_dept_id FROM department_link_closure WHERE dept_id = :target_dept_id
);
```

ทำแบบนี้ที่จุดที่แอปมือถือ query กิจกรรมตามหมวดหมู่/หลักสูตร ก็จะเห็นกิจกรรมที่โพสต์จากภาควิชาที่เชื่อมกันด้วยทันที
โดยไม่ต้องแก้อะไรที่ฝั่งเว็บแอดมินหรือฐานข้อมูลเพิ่มเติมอีก (ข้อมูล + วิวพร้อมอยู่แล้ว)

## ทำไมมีข้อมูลในฐานข้อมูลแล้ว แต่แอปมือถือยังไม่เห็นผล
มีข้อมูล (ตาราง `department_links` + วิว `department_link_closure`) อยู่ในฐานข้อมูลที่ใช้ร่วมกันแล้วก็จริง
แต่ **"มีข้อมูลในฐานข้อมูล" กับ "แอปเอาไปใช้" เป็นคนละเรื่องกัน** — เซิร์ฟเวอร์ของแอปมือถือมีโค้ด query ของตัวเอง
แยกออกจากเว็บแอดมินนี้โดยสิ้นเชิง (คนละเซิร์ฟเวอร์ คนละโค้ด แชร์แค่ฐานข้อมูล) ถ้าโค้ดฝั่งแอปมือถือยังเขียนแบบเดิม
คือ `SELECT * FROM events WHERE dept_id = X` เฉย ๆ มันก็จะยังไม่มองเห็น/ไม่ได้ใช้ตาราง `department_links` เลย
ต่อให้ข้อมูลในตารางนั้นถูกต้องครบถ้วนแค่ไหนก็ตาม

เปรียบเทียบง่าย ๆ: การเพิ่มคอลัมน์ใหม่ในสเปรดชีต ไม่ได้แปลว่าโปรแกรมอื่นที่เคยอ่านสเปรดชีตนั้นจะเห็นคอลัมน์ใหม่
อัตโนมัติ — โปรแกรมนั้นต้องถูกแก้โค้ดให้ไปอ่านคอลัมน์ใหม่ด้วยถึงจะเห็นผล เซิร์ฟเวอร์แอปมือถือก็เช่นกัน
ต้องมีคนไปแก้ query ในโค้ดฝั่งนั้น (เพิ่ม `JOIN`/`IN (SELECT ...)` กับวิวด้านบน) ถึงจะเห็นผลจริงตอนนิสิตเปิดแอป

## หมายเหตุ
- ตารางนี้สร้างและ seed ข้อมูลอัตโนมัติแล้วตอนเซิร์ฟเวอร์เว็บแอดมินเริ่มทำงาน (ไม่ต้องรัน SQL เอง)
- ถ้าในอนาคตมีภาควิชา/หลักสูตรใหม่ที่ต้องเชื่อมกันเพิ่ม ให้แจ้งทีมเว็บแอดมินเพื่อเพิ่มคู่ใหม่ในตารางนี้
  (หรือ INSERT ตรง ๆ ผ่าน phpMyAdmin ก็ได้ เพราะโครงสร้างตารางเรียบง่าย ไม่มี logic ซับซ้อน)
